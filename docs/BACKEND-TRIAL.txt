Failures encountered and repaired
---------------------------------
1. Reported source bundle exceeded 8 MiB because npm-cache.tar.gz was 40,050,000 bytes.
   Full lossless recompression still exceeded the limit. The fixed dependency versions
   remained unchanged; the compact runtime removes unused build tooling and package
   files while preserving the requested application commands and unchanged Ponder core.
2. The first compact bootstrap failed to resolve schema imports from a virtual URL.
   The alias hook now resolves virtual-module imports relative to the project config.
   Subsequent complete live runs, including the fresh offline run, passed.
3. Initial packer validation correctly rejected pruning viem's real actions/test API
   modules as upstream tests. Runtime-selected files and declarations now take
   precedence over directory pruning. No incomplete archive was used for acceptance.
4. The scratch unpacked registry files lacked npm's executable bits for CLI bins;
   the installer now explicitly sets executable bits and links only tsc/prettier.
   Fresh-install typecheck and formatting passed.

Operational limits and checks not run
------------------------------------
NOT RUN / not validated: public deployment/RPC, funded wallets, PostgreSQL production,
permanent hosting, cloud services, Docker, other OS/CPU offline installs, deep chain
resets, large-scale load tests, independent security review, Slither/Mythril.
No production readiness or platform-wide hosting capability is claimed.

The reorg window is 120 seconds of chain timestamps, not 120 confirmations. Latest
results are provisional. Window-finalized labels describe retained rollback history,
not consensus finality. Data freshness is always read from the status envelope.
The one-JSONB-row projection is intended for small local datasets; updates rewrite
that snapshot. History pagination is a live provisional view. Freeze at a common block
for multi-page audit comparisons; reconciliation needs historical state from the RPC.

Operators supply the local RPC, chain ID, actual contract/deployment receipt, database
location and API port. Startup pins chain ID/genesis/deployment hash/code hash/address
and reorg settings, refusing mismatches instead of mixing deployments or deleting DBs.
Keep Anvil alive across restarts, use a separate DB for a new chain/deployment, and
monitor errors/lag. Stop before archiving data. Only a separate transaction-capable
application or harness may expire bookings or pay refunds. This backend never does.
